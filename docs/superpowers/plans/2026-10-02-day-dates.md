# Day Dates and One-Row Mobile Tabs Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Seven mobile day tabs fit on one row, and a board's header shows the weekday and date (like "Sunday 09/27") once something on it is checked off; a ticked rest day shows its date too.

**Architecture:** The exercise date is derived, not stored: it is the earliest date among this week's log entries for the cards in the column (check-offs already write dated log entries). Only the rest day needs one new field, `week.restOn`, stamped when Rest day is ticked and persisted like `week.rest`. The mobile fix is a one-line grid change.

**Tech Stack:** React 19, zustand, vitest (Node, no DOM), SheetJS (`xlsx`), oxlint.

**Spec:** [docs/superpowers/specs/2026-10-02-day-dates-design.md](../specs/2026-10-02-day-dates-design.md)

## Global Constraints

- Branch `day-dates` (already created from `main`); one commit per task; commit messages end with `Co-Authored-By: Claude Sonnet 5.5 <noreply@anthropic.com>`.
- Label format: long weekday name plus zero-padded month/day, e.g. `Sunday 09/27`, from a fixed English name list (not the locale).
- The date shown on a board is the **earliest** `d` over `logs[item.ex]` entries with `e.slot === card.id` and the viewed week; nothing is blocked or restricted.
- `week.restOn`: string `YYYY-MM-DD`, present only while `week.rest` is set, never `null`; `normWeek` drops it otherwise or when malformed. Ticking Rest day stamps it with `defaultLogDate(weekStart)` only if none is set; unticking deletes it; moving the rest day (ticking another day, or the swap arrows) keeps it.
- Excel `Check-offs` sheet: a `restOn` row kind; the reader runs the value through the existing `dateText` helper so a re-save that turns it into a date still imports.
- Phone tabs: `grid-template-columns: repeat(7, minmax(0, 1fr))`; tab text must fit at 360 px. The tabs themselves get no date.
- WCAG 2.2 AAA: the date line is plain text in the header (not part of the section's accessible name); keep the muted/ink colors from existing tokens.
- Code style: match the surrounding code (dense one-liners, comments only for non-obvious rules). Tests: `npx vitest run <file>`; all `npm test`; lint `npm run lint`; build `npm run build`.

## Review Focus

1. Log entries from other weeks, or for cards not in the column, must not leak into a board's date (e.g. a card moved out of the column, or last week's entry for the same slot). Tests in Task 1.
2. A stale `restOn` without a rest day, or a malformed one (hand-edited JSON, Excel cell turned into a date serial), must be ignored or normalized, never shown or crash. Tests in Tasks 1 and 2.
3. Moving the rest day must keep its date; unticking must clear it so ticking again stamps a fresh one. Test in Task 2.
4. Hand-logged sessions count for the date; unchecking an auto check-off removes the label. Tests in Tasks 1 and 2.
5. Seven tabs on one row at 360 px, including "D3 Rest" and counts like "10/12". Manual check in Task 3.

export const fmtDayDate = s => { const d = parseDate(s); return `${DAY_NAMES[d.getDay()]} ${pad(d.getMonth() + 1)}/${pad(d.getDate())}`; }; // "Sunday 09/27"

```js
// The day a board was worked: the earliest date among this week's log entries for the cards in it.
export function dayDate(cards, logs, wk) {
  let first = null;
  cards.forEach(s => s.items.forEach(it => (logs[it.ex] || []).forEach(e => { if (e.slot === s.id && e.d && weekOfEntry(e) === wk && (!first || e.d < first)) first = e.d; })));
  return first;
}
```
